# 名片簿

名片 OCR 結果的瀏覽介面，一個沒有建置步驟的 PWA（純 HTML / CSS / JS）。

## 這是什麼

一條自架的名片數位化流程的前端：

```
手機拍照 → Telegram bot ─┐
                          ├→ n8n → Claude 辨識 → Google Drive 存原圖
Gmail 名片附件（排程匯入）─┘                   → Google 試算表存欄位
                                                      ↓
                                                 本頁面讀寫
```

辨識與儲存都在自己的機器與帳號上，這個頁面只負責看與改。

## 功能

- 搜尋姓名、公司、職稱、信箱、電話、備註
- 雙語名片正反面合併：同一個 email 視為同一人，中文名與英文名都保留
- 點擊撥號、寄信、開網站；分機會轉成撥號暫停格式，不會被截斷
- 匯出 vCard 存進手機通訊錄
- 手寫備註，寫回試算表
- 釘選常用名片到最上面
- 刪除名片（軟刪除，試算表留著資料，清單預設不顯示）
- 名片畫面從左緣往右滑，回到清單
- 名片原圖在裝置上留快取（Cache Storage，上限 150 張），同一張只下載一次
- 清單出現時就在背景預抓釘選的與最前面幾張，手指按下某一列時插隊先抓那張
- 離線可開，顯示上次抓到的資料

## 設定

部署後第一次開啟時輸入兩項，都只存在該裝置的瀏覽器裡：

| 欄位 | 說明 |
| --- | --- |
| 伺服器位址 | n8n webhook 的基底網址，結尾是 `/webhook` |
| 存取密碼 | n8n 端 Header Auth 憑證的值，標頭名為 `X-API-Key` |

兩者都不在原始碼裡——這個 repo 是公開的。

## 後端需要的三個端點

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| `GET` | `/cards` | 回傳名片陣列 |
| `POST` | `/card-note` | 以 `卡片ID` 定位，寫回 `備註` / `釘選` / `已刪除` |
| `GET` | `/card-image?id=<Drive 檔案 ID>` | 代理下載名片原圖 |

三者都以 `X-API-Key` 標頭驗證，並需允許此站台的 CORS 來源。

原圖必須走 `/card-image` 代理，不能直接連 Google Drive 的縮圖網址：瀏覽器不會把 Drive 的
`SameSite=Lax` cookie 送到跨站的圖片請求上，所以私有檔案在這個網域底下永遠載不出來。

## 部署

三個檔案放進開啟 GitHub Pages 的 repo 即可，沒有相依套件、不需要建置。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `index.html` | 整個應用程式 |
| `manifest.json` | 加到主畫面用的設定 |
